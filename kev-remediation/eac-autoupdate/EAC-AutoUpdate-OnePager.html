EAC Auto-Update — automated third-party KEV remediation

A scheduled Logic App correlates the live CISA KEV catalog against Defender vulnerability exposure, then for every affected device either adds it to an Enterprise App Catalog auto-update app's group (Intune patches it) or opens a ServiceNow ticket + email when it can't be auto-patched.

API-direct correlation No Sentinel dependency Firewall-safe (via Intune CDN) Least-privilege identity Commercial + GCC

Match to catalog app
is this software an EAC auto-update app in eac-apps.json, not excluded?

YES — auto-patchable

Translate the device (MDE→Entra), then add it to the KEV-Remediate-<app> group. IME installs the latest catalog version from *.manage.microsoft.com. When MDVM next reports Fixed, the device is removed from the group.

change mechanism · no device→vendor egress

NO — can't auto-patch

No mapping, excluded, not in the catalog (e.g. Edge), or device not Entra-resolvable → open a ServiceNow ticket + email, tagged with the priority summary and [EXPEDITE] when overdue.

fallback · ../fallback-ticketing/
02

One-time setup — eager pre-staging

Per app · admin

Onboard catalog app

Creates a windowsAutoUpdateCatalogApp that auto-tracks the latest catalog version, its KEV-Remediate-<app> device group, and a Required assignment.

Dormant until used

Empty groups

Groups start empty — no members, no installs. The runtime only ever manages group membership; it never creates apps or groups.

Least privilege

Grant the identity

The runtime managed identity gets read + membership + mail only. App/group create rights live solely in the admin onboarding step.
