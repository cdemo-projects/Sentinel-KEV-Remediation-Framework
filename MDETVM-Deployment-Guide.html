Deployment Guide

MDETVM Solution

End-to-end steps to deploy the Logic App, grant permissions, and populate the KEV workbook in Microsoft Sentinel.

Steps: 1Deploy ARM 2Get MI ID 3Graph Permission 4Verify DCR 5Trigger & Verify 6Deploy Workbook

Before you start

  • Global Administrator or Privileged Role Administrator in the tenant
  • Owner or User Access Administrator on the Azure subscription
  • Microsoft Sentinel already deployed with a Log Analytics workspace
1

Deploy the Logic App

Deploy the ARM template via the Azure portal
Manual
  1. In the Azure portal, search for Deploy a custom template
  2. Select Build your own template in the editor
  3. Paste the contents of MDETVM-LogicApp.json → Save
  4. Fill in the parameters:
    PlaybookNameMDETVM
    WorkspaceName<your Log Analytics workspace name>
    WorkspaceResourceGroup<resource group containing the workspace>
  5. Select Review + create → Create and wait for the deployment to complete
ℹ️ The ARM template automatically creates the system-assigned managed identity, the DCR, and grants Monitoring Metrics Publisher on the DCR. No extra portal steps needed for those.
2

Copy the Managed Identity Object ID

You'll need this for Step 3
Manual
  1. Portal → Logic Apps → open MDETVM
  2. Left nav → Settings → Identity → System assigned
  3. Copy the Object (principal) ID — save it, you'll paste it twice in Step 3
3

Grant Vulnerability.Read.All to the MI

Requires Graph Explorer — this is the only step that uses Graph
Graph API
  1. Go to Graph Explorer
  2. Sign in with your Global Admin or Privileged Role Administrator account — confirm the tenant name in the top right is the correct tenant
  3. Click your profile photo → Modify permissions → search for AppRoleAssignment.ReadWrite.All → Consent
  4. Set the method to POST and the URL to:
https://graph.microsoft.com/v1.0/servicePrincipals/<MI-Object-ID>/appRoleAssignments
Request Body

Click the Request body tab in Graph Explorer and paste:

{ "principalId": "<MI-Object-ID>", "resourceId": "fc780465-2017-40d4-a0c5-307022471b92", "appRoleId": "41269fc5-d873-4a86-8347-c2e0275ff02d" }
ID Reference
principalId <MI Object ID from Step 2> Per deployment
resourceId fc780465-2017-40d4-a0c5-307022471b92 Constant
appRoleId 41269fc5-d873-4a86-8347-c2e0275ff02d Constant
Expected Response Codes
CodeMeaningAction
201 CreatedSuccess ✓Proceed to Step 4
200 OKAlready assignedProceed to Step 4 — you're good
403 ForbiddenInsufficient permissionsConfirm signed in as Global Admin and AppRoleAssignment.ReadWrite.All is consented
404 Not FoundWrong Object ID or wrong tenantVerify the MI Object ID from Step 2 and confirm correct tenant sign-in
400 Bad RequestMalformed request bodyCheck JSON for typos; confirm all three IDs are present
4

Verify the DCR Permission

Should already be set — quick confirmation only
Verify
  1. Portal → Data Collection Rules → open the DCR created in Step 1
  2. Left nav → Access control (IAM) → Role assignments
  3. Confirm Monitoring Metrics Publisher is assigned to MDETVM
If it's missing — add it manually
  • Add → Add role assignment → Monitoring Metrics Publisher
  • Members → Managed identity → Select members → Logic App → MDETVM → Assign
⏱️ If you just added this manually, wait up to 30 minutes before running Step 5. A 403 from the ingestion endpoint before then is propagation delay, not a failure.
5

Trigger the Logic App & Verify Data

Confirm data is flowing into Sentinel
Manual
  1. Portal → Logic Apps → MDETVM → Overview → Run Trigger → Run
  2. Watch the run history — should show Succeeded
  3. If it fails, click the run → expand each action to find the step and HTTP response code that errored
  4. Wait 5–10 minutes, then go to Sentinel → Logs and run:
MDETVM_CL | take 10
✅ If rows return, data is flowing and the workbook will populate.
6

Deploy the Sentinel Workbook

Paste the workbook JSON from GitHub
Manual
  1. Portal → Microsoft Sentinel → Workbooks → Add workbook
  2. Click Edit → code editor icon (</>)
  3. Copy the workbook JSON from GitHub: MDETVM-KEV-Workbook.json ↗ and paste it into the editor
  4. When prompted for workspaceId, enter the full resource ID of your Log Analytics workspace:
/subscriptions/<sub-id>/resourceGroups/<rg>/providers/Microsoft.OperationalInsights/workspaces/<workspace-name>
  1. Save — give it a name and select your region
